# 成果文件的事务与维护

V38 保持 V37 的证据抽取、核验、图表、报告与静态网页协议。此次只修改成果持久化和耗时记录，不修改事实标准、模型提示词或检索配置。

API、worker 和维护命令通过同一共享目录的操作系统文件锁互斥。锁覆盖文件写入、业务事务提交或回滚，进程退出会释放锁。文件写入会 flush/fsync；取消发生时先等待本地写入线程结束，再执行回滚清理，避免删除后迟到线程重新写出文件。

事务失败后只清理本次新建且数据库中确实不存在成果记录的文件。提交确认不明确或数据库不可用时保留文件，交给后续维护检查；不得因为连接异常删除可能已提交的成果。已有成果不进入回滚清理列表。

维护命令默认只检查 24 小时以前的规范 UUID 文件，不删除业务成果或历史报告：

```powershell
docker compose --env-file .env -p zhixu-rag-v38 -f compose.yml -f artifacts/deployment_v1_38/compose.pinned.yml run --rm --no-deps api python -m app.artifact_cleanup
```

核对检查结果后，可添加 `--apply`，将无数据库记录的孤立文件移动到共享目录的 `.quarantine`。每次最多 100 个，可用 `--limit` 调整到不超过 1000。隔离是可恢复的同卷重命名，不会自动删除隔离内容；有数据库记录的文件没有自动过期策略。数据库不可用时维护失败并保留文件。

此锁面向单机 Docker 的共享 named volume 或本地文件系统，不宣称已经验证跨机器网络文件系统锁语义。正常纯问答不会获取成果文件锁；并发成果发布由锁串行化，等待最多 10 秒。

转换 trace 的 `elapsed_ms` 记录从 API 处理入口到成果与 trace 写入前的实际耗时（包括文件锁等待、证据与版本校验和文件保存）；不包括最后数据库提交确认及响应网络传输。主回答的成果节点记录实际耗时，并将同一数值放入持久 SSE 的 `agent_step` 事件；不依靠刷新来补出耗时。
