# 工程收尾版本 · engineering-closeout-v1

本版本完成真实环境联调与小样本质量验证。grade冻结5题三档15个单元由12个符合标准提升为15个，并保留资料外拒答边界；该语义实验及414次调用记录保留，本轮工程收尾不重复题目、不新增百炼调用。质量与延迟的权衡仍按原实测约5秒→约10秒记录。

本轮代码格式问题属于Ruff，涉及vector_models.py；不涉及文件上传或解析。ORM生命周期只允许每个进程一组活动数据库配置，拒绝并行重初始化；关闭连接后清理business/vectors的SQL执行器缓存，以免顺序切换数据库方言时复用错误SQL。用户请求不选择数据库环境；API和worker分别运行，每个使用固定双库配置。不同开发、测试、生产环境继续优先使用独立进程，不支持同一进程挂载多个应用环境。

## 本机运行

保留现有`.acceptance/round2/database.env`和数据库卷，不重新生成密码。启动脚本默认镜像为`rag-acceptance-r2-backend:engineering-v1`，从既有CSV读取模型凭据但不打印。

```powershell
cd D:\Project\RAG高级项目\source\rag-platform-reproduction
.venv\Scripts\python.exe scripts/acceptance_compose.py start --real-models
.venv\Scripts\python.exe scripts/acceptance_compose.py status
```

前端：http://127.0.0.1:18088；API：http://127.0.0.1:18086。API/worker镜像与源码哈希需要与本轮交付清单一致。`start`不构建镜像、不调用模型；实际提问、入库和评测才产生调用。

停止时使用`python scripts/acceptance_compose.py stop`，保留卷。可显式用`--backend-image rag-acceptance-r2-backend:grade-v2`回到前一修订，但不要将其视为本轮代码。运行日志使用新的`artifacts/runtime_startup`文件，不覆盖历史报告。

## 冻结与复验

```powershell
.venv\Scripts\python.exe -m scripts.freeze_release verify --output artifacts/engineering_closeout_v1_20261002/release_manifest.json
.venv\Scripts\ruff.exe check app scripts tests
.venv\Scripts\ruff.exe format --check app scripts tests
.venv\Scripts\python.exe -m pytest -q -m 'not integration' --basetemp=.acceptance/tmp/local_unit_recheck
```

真实双库测试必须使用新的空专用数据库，并设置`TEST_BUSINESS_DB_URL`、`TEST_VECTOR_DB_URL`、`ACCEPTANCE_ISOLATED_DATABASES=1`；先执行迁移，再独立进程运行`pytest -m integration`。不得对现有业务数据执行测试夹具的清理。虽然本轮已复验同进程混合方言场景，环境隔离仍优先采用独立进程。

演示验收使用另外两条真实数据库连接、独立API和worker进程以及Demo模型，不接入百炼。浏览器界面功能通过不代表Demo模型能验证grade语义；语义结论仍来自保留的真实模型实验。新机器从零setup、OCR、长期压力与备份恢复仍须另行验收。

公开源码清单只含源码、配置模板和启动/测试脚本；密钥、私有环境、数据卷和上传文件保留本机，不进入源码包。
