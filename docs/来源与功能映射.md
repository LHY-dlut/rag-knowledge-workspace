## 对 Gemini 提示词的具体校正

| 问题 | 复现决策 | 原因 |
|---|---|---|
| PostgreSQL写15，但图是18 | 默认PG18；可使用兼容的PG15另行部署验证 | 遵循用户所附最新图 |
| 只实现父子切分 | 支持三种切分，按知识库设置 | 补充图明确三种资料的不同选择 |
| 两路统一Top20 | 三档预设分别5、8、10；可自定义 | 图中调优有明确档位 |
| 原问题+扩展没有预算定义 | 保留原问题，总计最多4条；HyDE另加一条密集召回 | 对齐“3个变体共4条”并限制费用 |
| 幻觉失败回rewrite | 回generate，用同一证据重新回答 | 状态图明确这样连线；资料不足才重新检索 |
| 重试3次是否含第一次 | 采用额外重试3次，因此最多4轮；文档明确说明 | 避免 off-by-one，允许设置2表示总计3轮 |
| 生成立即作为最终SSE消息 | 草稿实时流出，检查通过后提交；失败草稿清除 | 核验结果出现前不能标记为最终答案 |
| gte-rerank-v2被假定OpenAI兼容 | 使用百炼原生HTTP接口 | 官方文档为该模型定义专门请求/响应形状 |
| 把RRF分数套余弦阈值 | hybrid无相似度阈值；dense用0.3；full用rerank0.05 | 分数属于不同量纲 |
| 四指标只是名称 | 实际LLM裁判、边界检验、服务端计算比例/AP、留存逐题结果 | 指标必须可计算、可查来源 |

余弦相似度的数学范围是[-1,1]，截图的“0–1”是经验描述，不能当作对全部向量成立的理论定义。

## 复现中新增的工程实现选择

- 15张业务表加1张向量表，覆盖可辨认功能。原项目的25张表名与列未知，不能用无作用的空表凑数。
- 父块位于业务库，子块与向量位于PG；双库采用“向量事务完成后发布ready”的可恢复协议，并以索引版本拦截生成期间变旧的证据。
- worker采用数据库持久任务和租约；demo在API中启动worker，双库模式独立进程运行。
- 业务隔离按owner_id；原项目管理员角色、组织共享、具体RBAC结构未知，本工程没有冒充还原这些设计。
- 三个工具选为search_knowledge、calculator、current_time；图片只明确数量，未提供原始三个名称。
- 模型密钥通过环境管理；模型页展示状态与连通测试。没有在业务表存储或前端回显Key。
- Context Precision采用返回证据的AP，另记相关证据比例；不是声称与RAGAS某版本逐行等价。
- 扫描PDF采用可选RapidOCR入口；本环境未执行OCR；旧版DOC/XLS需先转换成DOCX/XLSX。
- BM25为按知识库版本缓存的进程内索引，明确限制语料规模。大规模部署可替换该适配器。
