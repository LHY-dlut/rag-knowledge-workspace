在项目目录执行：

```powershell
.venv\Scripts\python.exe scripts/acceptance_compose.py status
.venv\Scripts\python.exe scripts/acceptance_compose.py start --real-models
```

脚本在内存中读取此文件夹原有百炼 CSV，不打印密钥。当前机器无需再提供 Docker、数据库地址或百炼凭据。隔离 Compose 项目名 `rag-acceptance-r2`；MySQL 端口 13307，PostgreSQL 端口 15433。随机数据库密码/JWT 保存在忽略目录 `.acceptance/round2/`，不进入源码包、构建上下文和报告。保留这些本地配置与隔离数据卷，以便重启。

停止本次环境而保留数据：

```powershell
.venv\Scripts\python.exe scripts/acceptance_compose.py stop
```

新机器、新目录首次部署：安装仓库锁定依赖后执行 `python scripts/acceptance_compose.py setup --real-models --credentials <百炼CSV完整路径>`。该分支新增于本轮，构成它的构建、迁移、启动步骤已分别实测；尚未在第二台干净机器从零执行该一键分支。不要删除原机器私有配置后直接对已有数据卷重新生成密码。

## 复验命令与隔离条件

本地单元、Mock 和 SQLite 组：

```powershell
.venv\Scripts\python.exe -m pytest --collect-only -q
.venv\Scripts\python.exe -m pytest -q -rs -m 'not integration' --basetemp=.acceptance/tmp/recheck_unit
```

真实双库组先准备**空的专用测试数据库**，在当前 PowerShell 会话的环境变量中配置 `TEST_BUSINESS_DB_URL`、`TEST_VECTOR_DB_URL`、`ACCEPTANCE_ISOLATED_DATABASES=1`。不要在命令行中打印连接字符串或将密码写入报告。迁移进程使用相同地址对应的 `BUSINESS_DB_URL`、`VECTOR_DB_URL`，并设置 `APP_MODE=production`、随机 `JWT_SECRET`、`MODEL_PROVIDER=demo`：

```powershell
.venv\Scripts\python.exe -m app.bootstrap
.venv\Scripts\python.exe -m app.bootstrap
# pytest 进程仅保留 TEST_* 和 ACCEPTANCE_ISOLATED_DATABASES；避免把 API 的工作进程开关覆盖到 Demo 测试。
.venv\Scripts\python.exe -m pytest -q -rs -m integration --basetemp=.acceptance/tmp/recheck_dual
```

两组分进程运行。锁定版本 Tortoise 的执行器缓存不能在同一进程中使用相同连接别名反复切换 MySQL/SQLite SQL 方言；本轮保留了混跑失败记录，没有据此删除任何测试。真实双库夹具要求空用户表，防止把验收清理应用到现存业务数据。

`tests/test_acceptance_lock_waits.py`、`test_acceptance_real_faults.py` 使用真实 MySQL 行锁和临时 CHECK 约束；约束仅作用于测试文档，在 finally 中解除。`test_acceptance_storage.py` 在当前 pgvector 表写入 260 条受控向量并保留实际 HNSW 执行计划。模型采用 Demo 的并发故障测试与真实百炼质量验收分开记录。

前端：`cd frontend` 后执行 `npm run test`、`npm run build`。现有 `package-lock.json` 未更改。浏览器脚本使用本机 Edge 和已有 Playwright 运行时。

小规模收费联调脚本是 `scripts/acceptance_real_dual.py`：必须明确设置隔离数据库环境；通过 `--credentials` 读取既有 CSV，通过 `--report` 指定新的证据目录；每轮上限 150 次请求。它会在检索前冻结样本和相关子块预标注，绝不从检索结果反推标签。不要直接反复运行作为大规模评测。
